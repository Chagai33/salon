## מה שנמדד בקוד

**שחרור משמרת מוחק את עצמו:**

```ts
// src/services/salonService.ts:402
export async function releaseShift(branchId: string, id: string) {
  await updateDoc(doc(shiftsRef(branchId), id), {
    assigneeMemberId: null, assigneeName: null,
    assignedAt: null, assignedBy: null,
    handoverState: 'none', handoverRequestedAt: null, handoverReason: null,
  });
}
```

⚠️ **אחרי הקריאה הזו המשמרת נראית בדיוק כמו משמרת שאיש לא נרשם אליה מעולם.**
מי נרשם, מתי נרשם, ומתי ביטל, שלושתם נמחקו באותה כתיבה.

**ובקשת מחליף שבוטלה מתנהגת אותו דבר**, `cancelHandoverRequest`, שורה 432.

**וכל שדות העקיבה שקיימים הם "מי כתב אחרון" ולא היסטוריה:**

| השדה | איפה | מה הוא יודע |
|---|---|---|
| `assignedBy`, `assignedAt` | `Shift` | **מי משובץ עכשיו**, ונמחק בשחרור |
| `attendanceSetBy`, `attendanceSetAt` | `Shift` | מי סימן נוכחות **אחרון** |
| `approvedBy`, `approvedAt` | `Member` | מי אישר את החבר |
| `setBy`, `setAt` | `AccessCode` | מי קבע את הקוד |

⚠️ **אין אוסף אחד שנכתב ואינו נמחק.**

## היומן

**רשומה שנכתבת ואינה נמחקת, שאומרת מי עשה מה ומתי.** ⚠️ **ולדבר הזה אין שורה
ב-[GLOSSARY](../GLOSSARY.md), ולכן אין לו שם במוצר**, והוספת השורה היא עצירה
שממתינה לבעל המוצר.

**אוסף משנה על הסניף, בסכמה סגורה:**

```
events/{eventId}
  at: number                  // מתי נכתב
  actorMemberId: string       // מי עשה, ונעוץ למי שמחובר
  action: enum                // הרשימה למטה
  shiftId: string?            // על מה
  shiftDate: string?          // כדי שהדוח לא יצטרך לקרוא את המשמרת
  subjectMemberId: string?    // על מי, כשזה אדם אחר
  detail: enum?               // ⚠️ enum, ולא טקסט חופשי
```

⚠️ **ואין בו שדה טקסט חופשי.** זה הכלל היחיד שמונע מהיומן להיות מצבור מידע
אישי, **ואותה אזהרה כבר נכתבה ברשומה
[07](07-the-duty-member-has-nowhere-to-report.md):** "דבר חריג" בשדה חופשי
יכול להיות דיווח על אדם.

### החוקים

```
allow create: if isActive(branchId) && request.resource.data.actorMemberId == request.auth.uid;
allow update, delete: if false;          // ⚠️ גם למנהלת
allow get:    if isManager(branchId) || resource.data.actorMemberId == request.auth.uid;
allow list:   if isManager(branchId);
```

⚠️ **"גם למנהלת" אינו החמרה מיותרת.** יומן שמי שנמצא בו יכול למחוק ממנו אינו
ראיה, **והמנהלת היא בדיוק מי שהיומן מתעד** כשהיא מחליפה קוד או משנה הרשאות.

⚠️⚠️ **ומה שחוק מסד אינו יכול להבטיח: שהיומן נכתב בכלל.** הכתיבה היא מהדפדפן,
**וחבר שמריץ את הפעולה ישירות מול המסד משנה את המשמרת ואינו כותב שורה.**
החוקים מונעים זיוף על אדם אחר ומחיקה, **ואינם מונעים שתיקה.**

**התיקון הוא אותה פונקציית ענן שחסרה לאכיפת הזכאות**, רשומה
[15](15-the-code-is-not-enforced-yet.md). **שני דברים, רכיב אחד**, ובלעדיו
היומן הוא עקיבה טובה ולא ראיה.

### ⚠️⚠️ שלושה דברים שהרשומה הזו קבעה ולא שרדו את הבנייה

**1. ⚠️⚠️ תפוגת 12 החודשים לא הייתה עובדת על הסכמה שנקבעה.**

הרשומה קבעה `at: number`, ושהתפוגה היא מדיניות `TTL` על השדה `at`.
**ומדיניות `TTL` של Firestore מוחקת לפי שדה מטיפוס חותמת זמן בלבד.** שדה
מספרי אינו נמחק כלל, **ולכן השורות היו נשמרות לנצח, בשקט.**

✅ **התיקון:** `at` נשאר מספר, לדוח ולמיון, **ונוסף `expiresAt` כחותמת זמן**,
12 חודשים קדימה, והמדיניות יושבת עליו.

⚠️ **והחוק אוכף את הטיפוס**, `expiresAt is timestamp`, כי זו הייתה טעות שקטה
וצריך שהיא לא תחזור. ✅ **נמדד** בבדיקה "שדה התפוגה חייב להיות חותמת זמן, ולא
מספר".

⚠️ **ומה שלא נמדד: המחיקה עצמה.** האמולטור אינו מיישם מחיקת תפוגה, **והמדיניות
נפרסת בנפרד:**

```bash
firebase deploy --only firestore:indexes --project hasalon-dev
```

**2. ⚠️⚠️ החוקים כפי שנקבעו היו שוברים את ההאצלה של מנהל המערכת.**

הרשומה קבעה `allow create: if isActive(branchId)`. **ומנהל המערכת מאציל
תפקידים בסלון שנוצר לפניו, ושם הוא חבר שממתין לאישור.** השורה נכתבת באותה
אצווה של שינוי התפקיד, **ולכן האצווה כולה הייתה נדחית והאצלה הייתה מפסיקה
לעבוד.**

✅ **התיקון:** `isActive(branchId) || isPlatformAdmin()`. ✅ **ונמדד** בבדיקה
"ומנהל המערכת כותב גם כשהוא אינו חבר פעיל בסלון".

**3. ⚠️⚠️ "סכמה סגורה ולא טקסט חופשי" לא הייתה נאכפת בשום מקום.**

ארבע שורות החוקים שברשומה אינן אומרות דבר על השדות. ⚠️ **ו-`action` הוא
מחרוזת**, ולכן כל חבר פעיל יכול היה לכתוב ישירות למסד
`action: 'ביטל שלוש פעמים והוא לא אמין'` לתוך שורה שנשמרת 12 חודשים וקריאה
לכל מנהלת שתבוא.

⚠️ **והרשומה עצמה אמרה שזה הכלל היחיד שמונע מהדבר להיות מצבור מידע אישי.**
**קוד האפליקציה אינו יכול לאכוף אותו**, כי כתיבה ישירה למסד עוקפת אותו.

### ⚠️ מה שהוכרע אחרת ממה שהרשומה הציעה

**1. ✅ `detail` אינו נושא את מספר הימים שהייבוא נגע בהם.** הרשומה כתבה
*"importRan, ובכמה נגע"* תחת `detail: enum`. **מספר אינו enum**, ולכן נוסף
שדה `count`, והוא מספר בלבד. ⚠️ **והוא גם אינו טקסט חופשי**, ולכן הוא אינו
פותח את החור שהסכמה הסגורה סוגרת.

**2. ✅ `settingsChanged` כותב שורה לכל חלק שהשתנה.** `detail` נושא חלק אחד,
**ושמירה שנגעה בשעות ובחללים היא שני דברים ולא "ההגדרות".**

**3. ✅ ועמודת "האם הגיע" בדוח נקראת "נוכחות במשמרת".** הרשומה כתבה *"האם
הגיע באותה משמרת"*. ⚠️ **ומי ששחרר את המשמרת לא עשה אותה**, ולכן הנוכחות
שנרשמה עליה אומרת מה קרה למשמרת, ולא מה האדם עשה. **העמודה אומרת מה שהיא
מודדת.** ⚠️ **ו-`assumed` נקרא "התקיימה" ואינו "הגיע"**, כפי שהרשומה דרשה.

### ⚠️ ומה שהבנייה הוסיפה: הכתיבה אטומית

**כל שורה נכתבת באותה אצווה או אותה טרנזקציה של הפעולה עצמה.**

⚠️ **ולכן פעולה שהשורה שלה נדחתה אינה נכתבת בכלל.** אין מצב שבו משמרת שוחררה
והשחרור אינו מתועד, **וזה חזק יותר ממה שהרשומה ביקשה.**

⚠️⚠️ **ומה שזה עדיין אינו מבטיח, כפי שהרשומה אמרה:** כתיבה ישירה למסד מחוץ
לאפליקציה משנה את המשמרת ואינה כותבת שורה. **החוקים מונעים זיוף ומחיקה,
ואינם מונעים שתיקה.** התיקון הוא אותה פונקציית ענן, רשומה
[15](15-the-code-is-not-enforced-yet.md).
