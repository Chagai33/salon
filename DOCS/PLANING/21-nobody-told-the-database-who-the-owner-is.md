# 21 — אף אחד לא אמר למסד מי מנהל העל

> ✅ **סטטוס: נבנה ונמדד, 05/10/2026. 39 בדיקות מול אמולטור, כולן עוברות.**

## השאלה

> "אבל אני מנהל העל, למה אני לא יכול לפתוח סלונים?"

**כי שום דבר במסד לא אמר שהוא מנהל העל.** רשומה
[20](20-who-may-open-a-salon.md) סגרה את החור שבו כל אחד פותח סלון, **והותירה
את ההרשאה כדבר שנכתב בקונסולה.** כלומר בעל המוצר היה צריך לצאת מהאפליקציה
כדי לומר לה מי הוא.

⚠️ **וזו לא עבודה של המשתמש.** כניסה ב-Google מזהה ואינה מקנה, **ופעם אחת
בחיי המערכת צריך מישהו לומר מי מפעיל אותה.**

## התיקון: מסמך אחד, והוא הדלת

**`system/bootstrap`.** הראשון שנכנס תובע את המערכת, **ובאותה אצווה נוצר
המסמך הזה.** מהרגע שהוא קיים התביעה נחסמת לעולם.

```
match /system/{docId} {
  allow get: if signedIn();
  allow create: if signedIn()
    && docId == 'bootstrap'
    && request.resource.data.claimedBy == request.auth.uid;
  allow update, delete: if false;
}
```

⚠️ **ו-`update, delete: if false` הוא מה שהופך את זה לחד פעמי.** בלעדיו אפשר
למחוק את הדלת ולתבוע שוב.

**זה אותו מנגנון בדיוק של פתיחת סלון**, `getAfter` על אצווה של שני מסמכים,
רשומה [18](18-each-salon-is-a-tenant.md).

## ⚠️ ומה שהתיקון הזה עולה

**מי שנכנס ראשון הוא מנהל העל.** זה חלון מירוץ, והוא נסגר בתביעה הראשונה.

**הוא קיים רק עד שבעל המוצר לוחץ**, ועד אז הוא פתוח לכל מי שמגיע לכתובת
וחותם ב-Google. **זה נאמר כאן כדי שההכרעה תהיה שלו ולא שלי.**

**החלופה שנשקלה ונדחתה:** לקבע את המייל או את ה-uid בחוקים.
⚠️ **והמאגר ציבורי**, רשומה [08](08-the-repository-is-public.md).

## מה נמדד

**שש בדיקות חדשות:**

| מה | התוצאה |
|---|---|
| הראשון תובע את המערכת באצווה אחת | ✅ עובר |
| ⚠️⚠️ **והשני אינו תובע, גם באותה אצווה בדיוק** | ❌ נדחה |
| ⚠️ ואינו מוחק את הדלת כדי לתבוע שוב | ❌ נדחה |
| תביעה בלי מסמך הדלת | ❌ נדחה |
| תביעה בשם מישהו אחר | ❌ נדחה |
| מי שתבע פותח סלון | ✅ עובר |

## ומה שנבנה כדי שלא תהיה קונסולה בכלל

| מה | איפה |
|---|---|
| גוש התביעה, **מוצג פעם אחת ואז נעלם** | `ClaimSystem` ב-`SalonsPage` |
| מנהל העל אינו נעצר במסך ההמתנה | `BranchScope` ב-`App.tsx` |
| **והוא מגדיר את עצמו כמנהלת** בסלון שנוצר לפניו | `MembersPanel` |

⚠️ **והשורה האחרונה היא הסיבה שאין קונסולה.** בתל אביב אין מנהלת שתאשר את
בעל המוצר, **ומסך ההמתנה היה מסך ללא יציאה.**

## ⚠️ ומה שלא נבדק כאן, בהוראת בעל המוצר

**הבדיקות בדפדפן לא הורצו על השינוי הזה.** בעל המוצר עצר אותן, והן עולות זמן
ריצה. **`DOCS/PLANING/VERIFICATION-BUDGET.md` אומר במפורש לשקול.**

⚠️ **ומה שזה אומר בפועל:** שני הבאגים שהוא מצא בעצמו, המסך הריק והכפתור המת,
**הם בדיוק מה שבדיקת דפדפן תופסת.** בדיקות החוקים נשארות, כי שם יושבות
ההרשאות והן רצות בפחות מדקה.
