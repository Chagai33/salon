# 17 — הכניסה הראשונה לא יכלה לעבוד, לעולם

> ✅ **סטטוס: תוקן ואומת מול אמולטור, 05/10/2026.**
>
> **נמצא על ידי בעל המוצר באתר החי**, בניסיון ההתחברות השני. המסך הראה
> `Missing or insufficient permissions`.

## שלוש בעיות באותו מסך, ולא אחת

### 1. החוקים לא נפרסו

**זו הסיבה המיידית.** `firestore.rules` יושב במאגר, **ופרויקט Firebase חדש לא
יודע עליו כלום** עד ש-`firebase deploy --only firestore:rules` רץ.

**חוקי ברירת המחדל של Firestore חוסמים הכל**, ולכן כל קריאה נדחתה.

⚠️ **וזה היה כתוב ב-`CLAUDE.md`:** "הם עוד לא נפרסו ולא נבדקו מול האמולטור."
**ושוב, ההסתייגות הייתה נכונה ולא מנעה כלום.** רשומה
[16](16-the-selector-that-looped.md) מתארת בדיוק את אותו דפוס.

### 2. ⚠️ והבאג שהיה מתגלה גם אחרי הפריסה

**החוק על רשומת החבר היה:**

```
allow read: if isMember(branchId);
```

ו-`isMember` בודק `exists()` על רשומת החבר.

**בכניסה הראשונה האפליקציה קוראת את רשומת החבר של עצמה כדי לבדוק אם היא
קיימת.** הרשומה אינה קיימת, ולכן `isMember` שקרי, ולכן הקריאה נדחית, **ולכן
הרשומה לא נוצרת לעולם.**

⚠️ **ביצה ותרנגולת: כדי לקרוא צריך להיות חבר, וכדי להיות חבר צריך לקרוא.**
**אף אחד לא היה יכול להיכנס, גם אחרי פריסת החוקים.**

**התיקון:** `get` ו-`list` נפרדים.

```
allow get: if signedIn() && (memberId == request.auth.uid || isMember(branchId));
allow list: if isMember(branchId);
```

**כל מי שמחובר קורא את הרשומה של עצמו, קיימת או לא. סריקת כל החברים נשארת
לחברים.**

### 3. מירוץ: המאזינים נפתחו לפני שרשומת החבר נוצרה

`setUser(user)` רץ **לפני** ש-`ensureMember` מסיים. והמאזינים היו תלויים
ב-`user`, ולכן נפתחו מיד: **סריקה על `members` ועל `shifts` בזמן שרשומת החבר
עוד לא קיימת.** שתיהן דורשות חברות, ושתיהן נדחו.

**התיקון:** המאזינים תלויים ב-`member` ולא ב-`user`.

## ⚠️ והבעיה הרביעית, שהמשתמש ראה ולא הייתה אמורה להגיע אליו

**במסך הופיע `Missing or insufficient permissions`, באנגלית.**

`DOCS/PLANING/03-the-design-standard.md` אומר במפורש: ארבעה דברים אינם מגיעים
לדפדפן, **ושגיאת Firebase גולמית היא אחד מהם.**

**הקוד עשה `error.message` ושם אותו במסך.** נוסף `src/utils/errors.ts`
שמתרגם, **והוא אומר למשתמש מה הצעד הבא ולא מה קוד השגיאה:**

> "המסד עוד לא פתוח לאפליקציה. צריך לפרוס את חוקי ההרשאות ב-Firebase."

## האימות

**`npm run test:rules`, אמולטור Firestore, 16 בדיקות, כולן עוברות.**

**ובהן הבדיקה שתופסת בדיוק את הבאג הזה:**

```
⚠️ הבאג שנמצא בשטח: אפשר לקרוא את הרשומה של עצמי לפני שהיא קיימת
```

**ועוד מה שנבדק:** אי אפשר ליצור את עצמך כמנהלת, אי אפשר ליצור את עצמך כפעיל,
אי אפשר ליצור רשומה בשם מישהו אחר, חבר אינו מאשר את עצמו, מנהלת כן, זר אינו
סורק את רשימת החברים, ומי שאינו מחובר אינו קורא כלום.

⚠️ **ובדיקה אחת מתעדת פער ולא מונעת אותו**, בכוונה:

```
⚠️ וזה בדיוק הפער שברשומה 15: גם מי שלא השתבץ החודש קורא אותו
```

**היא עוברת, והיא מוכיחה שהקוד נגיש למי שאינו זכאי.** רשומה
[15](15-the-code-is-not-enforced-yet.md). **כשהפער ייסגר, הבדיקה הזו תהפוך
ל-`assertFails` והיא מה שיוכיח שזה נסגר.**

## מה שנלמד, ושווה יותר מהתיקון

**שלושת הבאגים האלה ורשומה [16](16-the-selector-that-looped.md) הם אותו דפוס:
משהו נכתב, נבדק בחלקו, והפער נרשם כהסתייגות במקום להיסגר.**

**הסתייגות כתובה אינה בדיקה.** `CLAUDE.md` אמר "לא נבדק מול האמולטור", והיה
אפשר להריץ את האמולטור באותו יום: **JDK היה מותקן, ו-`firebase-tools` זמין
ב-`npx`.**

**מה שהשתנה:** `npm run test:rules` הוא עכשיו פקודה, ו-`CLAUDE.md` מחזיק אותה
לצד `npm run build`.
