# 16 — הבורר שגרם ללולאה, והמסך שנשאר ריק

> ✅ **סטטוס: תוקן ואומת, 05/10/2026.**
>
> **נמצא על ידי בעל המוצר באתר החי**, אחרי העלייה הראשונה ל-Netlify. לא נמצא
> כאן, **כי שום מסלול שדורש התחברות אמיתית לא נבדק.**

## מה קרה

בעל המוצר נכנס ל-`hasalon.netlify.app`, התחבר, **והמסך נשאר ריק.** בקונסולה:

```
Uncaught Error: Minified React error #185
```

`#185` הוא **"Maximum update depth exceeded"**, כלומר לולאת רינדור אינסופית.

## הסיבה

`src/store/useStore.ts` החזיק בורר כזה:

```ts
export const selectShiftsByDate = (state: AppState) => {
  const map = new Map<string, Shift[]>();
  for (const shift of state.shifts) { ... }
  return map;   // ⚠️ Map חדש בכל קריאה
};
```

ו-`BoardPage` קרא לו ב-`useStore(selectShiftsByDate)`.

**zustand גרסה 5 עובד דרך `useSyncExternalStore`, והוא משווה בהשוואת זהות.**
בורר שבונה `Map` חדש מחזיר הפניה חדשה בכל רינדור, React מסיק שהמצב השתנה,
מרנדר שוב, והבורר בונה `Map` חדש. **זו הלולאה.**

⚠️ **ושני בוררים היו כאלה:** `selectShiftsByDate` ו-`selectActivityByDate`.
`selectOpenShiftCount` ו-`selectHandoverCount` מחזירים מספר, **ומספר משווה
בערך ולא בהפניה**, ולכן הם לא השתתפו.

## השחזור, ומה שהוא הוכיח

**נבנו שתי חבילות, הישנה והחדשה, והורצו זו לצד זו מול אותו רכיב בדיקה:**

| | מה המסך הראה | שגיאת לולאה |
|---|---|---|
| **הדפוס השבור**, הבורר שבונה `Map` | **ריק** | ✅ React error 185 |
| **הדפוס המתוקן**, `useMemo` ברכיב | `ימים: 0` | אין |

**הרכיב בשני המקרים עשה את אותו דבר בדיוק.** ההפרש היחיד הוא איפה נבנה
ה-`Map`.

## התיקון

**הבוררים שבנו אובייקט הוצאו מה-Store והפכו לפונקציות עזר**,
`groupShiftsByDate` ו-`groupActivityByDate`. **הרכיב בוחר את המערך הגולמי
וגוזר ב-`useMemo`:**

```ts
const shifts = useStore((state) => state.shifts);
const shiftsByDate = useMemo(() => groupShiftsByDate(shifts), [shifts]);
```

**הכלל נכתב בראש `useStore.ts`:** בורר מחזיר ערך פרימיטיבי, או הפניה שכבר
קיימת ב-Store. **כל גזירה שבונה אובייקט נעשית ב-`useMemo` בתוך הרכיב.**

## ⚠️ ומה שזה אומר על איך נבדק כאן

**הלוח כן נבדק בדפדפן לפני העלייה**, ועבד. **אבל הוא נבדק מול
`src/dev/BoardPreview.tsx`, שמעביר נתונים כ-props ואינו נוגע ב-Store בכלל.**

**כלומר הבדיקה עקפה בדיוק את הקוד שנשבר.**

`CLAUDE.md` אמר את זה במפורש באותו קומיט: "לא אומת: שום מסלול שדורש התחברות
אמיתית ל-Google. הלוח נבדק מול נתונים מומצאים ולא מול Firestore חי."

⚠️ **ההסתייגות הייתה כתובה ונכונה, והיא לא מנעה כלום.** היא תיארה את הפער
במקום לסגור אותו.

**מה שהיה סוגר אותו:** תצוגת הבדיקה הייתה צריכה למלא את ה-Store ולקרוא ממנו,
ולא לעקוף אותו. **זה היה תופס את הלולאה על המכונה הזו.**

## הבאג השני באותו דיווח

**בקונסולה הופיעו גם שש הודעות:**

```
Cross-Origin-Opener-Policy policy would block the window.closed call
```

**כניסה עם Google נפתחת בחלון קופץ, ו-Firebase בודק אם הוא נסגר דרך
`window.closed`.** מדיניות COOP ברירת המחדל חוסמת את הבדיקה.

**התיקון ב-`netlify.toml`:** כותרת `Cross-Origin-Opener-Policy` בערך
`same-origin-allow-popups`. ההגנה נשארת, והחלון הקופץ יכול לדבר עם הפותח.

⚠️ **והתיקון הזה לא אומת מול האתר החי**, כי כותרות של Netlify אינן קיימות
ב-`vite preview` מקומי. **הוא ייאמת בעלייה הבאה, בקונסולה.**
